# 监控策略优先：实现与本地验收

日期：2026年11月12日。此文覆盖此前以日志采集/仓库为核心的设计重点；不是发行版本或部署说明。

## 1. 新执行链

Console → Fleet → Runtime(policy模式) → MonitoringService → PolicyEngine：

- runtime不启动旧channels/logs/events/report采集任务，启动policy-checks/notifications/retention。
- 调度器每秒检查到期任务，每个来源single-flight；渠道、错误、报告独立，余额请求最多4并发。慢用户不会阻塞下一轮渠道检查。
- 每个实际检查预算45秒。来源失败指数退避至15分钟；当前结果标未知，保留上次已确认业务状态。
- 仅完整分页才用于渠道比较。手动禁用不算故障，也不作为恢复证据。只有启用状态或确实重新出现才确认恢复。
- 错误检查仅type=5，固定增量时间窗+重叠去重。首次默认从now建基线，不追发旧错误；只有完整成功窗口才推进policy:error_cursor。重启不靠本地业务日志恢复。
- 请求错误记录是event，不自动进入resolved。告警模板只做白名单占位符替换，错误证据和通知脱敏。
- 用户余额走指定用户详情，quota必须存在；HTTP错误、缺字段、超时都不能生成0余额。独立阈值/恢复阈值/确认次数/间隔/冷却/启停/目标。
- 已投递目标的收据不会因编辑绑定名称而失效；整体部分失败重试只处理尚未成功的目标。网络投递仍是at-least-once，接收端与回执写入间崩溃时无法保证严格exactly-once。

## 2. 默认与注意项

| 项目 | 默认 |
|---|---|
| 渠道状态 | 启用，60秒，连续1次，冷却300秒 |
| HTTP错误 | 保留原启停；新建默认停用，120秒，400/500，首次回看0 |
| 错误窗口 | 单片300秒，重叠30秒，成功后推进 |
| 来源失败 | 启用，连续3次，恢复通知开启 |
| 余额 | 新增默认停用；平台默认300秒，可逐用户覆盖 |
| 日报/周报 | 默认停用，按平台时区独立调度 |
| 通知目标 | 空列表表示本平台所有订阅此事件的Webhook；可选指定目标 |

保存策略后立即应用，不需要重新连接机器人或重启NewAPI。改变错误规则会丢弃旧规则尚未发送的冷却计数，已入队通知保持原有路由。重新启用错误检查重新建基线；首次回看只在建基线时生效。手动复查是正式规则执行，可能触发正式告警，不是测试消息。

## 3. 数据边界

新增schema v4仅增加monitor_checks、monitor_states及outbox的binding_ids。保留配置、当前渠道快照/余额、游标、状态、脱敏样本、通知回执。旧表不破坏性删除，迁移前在线SQLite备份保存在本地artifacts/2026-11-12-policy-first。回滚须停止本监控服务并恢复迁移前数据库与旧源码；不允许把旧schema程序直接指向新库。

查询与报告：DataQueries向绑定平台请求完整、受限窗口，内存聚合；最多4个日志窗口，缓存30秒，不写业务logs，不移动监控游标。渠道查询缓存15秒。完整性仅代表当前令牌可见且平台仍保留的记录，上游缺失/已清理数据不能补造。大窗口超过预算明确失败，请缩小查询。

旧CLI/serve入口为兼容保留，仍可使用旧采集机制；新独立网站使用console入口。旧数据/旧告警保留作历史，不纳入新策略当前异常计数。切换时对旧采集器alert/daily/error前缀遗留待发通知标记historical，暂停自动补发，不删除内容；需要发送时通过通知投递页面显式重试。本机共609条旧渠道告警已暂停，避免后续新增Webhook时集中刷屏。

## 4. 页面与接口

前端：监控工作台、监控策略、告警记录、通知投递、逐用户余额、报告调度。渠道/用户/日志/按需统计/问答均为辅助查询。所有UI使用现有pure-admin、Element Plus/PureTable、设计tokens；无注册或新增角色。

全部管理接口沿用登录Cookie+CSRF，平台ID固定作用域：

- GET /console/api/platforms/{id}/monitoring：config、samples、errors、execution、last_run。
- PUT 同一路径：校验策略与同平台Webhook引用，热更新；不重连机器人。
- POST /console/api/platforms/{id}/monitor-runs：{request_id}，返回202。请求ID幂等、同平台并发复查去重，停用平台返回409。
- GET /console/api/platforms/{id}/notifications：page默认1/page_size默认20最大100，脱敏投递结果。
- POST /console/api/platforms/{id}/notification-retries：{notification_id,request_id}，仅dead或historical（历史停发）可重试，重复请求不重复重置。
- POST /console/api/platforms/{id}/alert-previews：纯示例预览，不发送消息。
- 策略显式引用的Webhook不能直接删除或取消所需事件订阅（409）；先解除策略引用，或选择停用绑定。
