# Webhook 错误告警：日志时间与请求追踪字段

日期：2026 年 11 月 14 日。本说明已按用户最新要求修订。

## 展示要求

- 通知中删除“错误码”和“告警时间”两行。
- “错误日志时间”只取该条原日志的 `created_at`，不取告警生成、轮询或投递时间。
- 不再强制显示北京时间或人为加减小时；格式化规则与本监控系统日志页一致，使用当前平台已有的 `timezone`。
- 同时提供原日志 ID 和可用的请求 ID，辅助核对同一条记录。时间可能重复，不能单靠秒级时间保证唯一。

不增加配置项或依赖，不修改数据库表结构，不采集额外全量日志，不修改上游 NewAPI。日报、周报及其待处理问题保持不变。

## 字段语义

| 模板占位符 | 来源及含义 | 缺失时 |
| --- | --- | --- |
| `{log_time}` | 原日志 `created_at`，按当前平台日志页既有时区格式化 | 显示“未提供”，不以告警时间替代 |
| `{log_id}` | 日志接口原记录的 `id` | 显示“未提供”，不使用本地告警 ID 冒充 |
| `{upstream_request_id}` | 日志的 `upstream_request_id` | 显示“未提供” |
| `{request_id}` | 日志的 `request_id`，是 NewAPI 平台请求 ID | 显示“未提供”，不冒充上游请求 ID |

NewAPI 官方日志接口返回的是秒级 Unix 时间戳，不是用户浏览器中已经排版好的时间文本。原始 `created_at` 以整数保留在现有错误样本 JSON 的 `log_created_at` 中，未修改原时间值。渲染时使用当前平台已有时区，并与本监控日志页采用相同的中文日期、时分秒格式；不额外做固定的 +8/-8 小时偏移。

**对照限制：** 服务不能知道另一网页浏览器当前使用的时区。若上游 NewAPI 网页的显示时区与本监控平台已有时区不同，钟面时间仍会不同；不能声称已经自动复制了上游网页的显示文本。应将已有时区与实际查看日志的口径保持一致，并结合日志 ID、平台请求 ID 或上游请求 ID 核对。ID 的可用性与具体上游版本、存储及接口有关，不承诺所有接口返回的展示序号跨查询永久不变。

官方 `model/log.go` 分别定义 `request_id`、`upstream_request_id`，二者不可混用。解析优先读取日志顶层字段；错误日志也兼容同名字段在 `other` 对象或 JSON 字符串中的形式。仅保留有界、单行 ASCII ID，并继续对配置密钥脱敏；不采用拉取日志这次 HTTP 响应的请求 ID，不从错误正文猜测 ID。

## 旧模板与冷却聚合兼容

- 已保存的旧模板在加载时移除含 `{error_code}` 或 `{time}` 的旧行，以及独立的“错误码”“告警时间”“时间”标签行。
- 旧 `{log_time}` 行中固定的“北京时间”后缀也会移除。若模板只剩被删除字段，则回退到当前默认模板，避免平台因空模板停止监控。
- 错误码仍保留用于筛选、同类错误分组和日志查询；本次只删除通知中的独立展示行。
- 未包含日志时间、日志 ID、上游请求 ID 占位符时自动补入；已有对应占位符则保留自定义位置，不重复追加。
- 上游请求 ID 缺失但有平台请求 ID 时，另加“平台请求 ID”一行。
- 默认模板和自动补入的追踪字段位于长错误正文之前；自定义模板若将字段放在长正文之后，仍需注意消息截断限制。
- 冷却聚合后，日志时间、日志 ID、请求 ID、错误信息对应同一条代表性错误样本；累计次数仍表示同类错误数量。
- 渲染使用持久化的原始时间戳，因此重开数据库或调整当前平台已有显示时区后，不会把旧的格式化文本再次平移。
- 升级前仅保存过强制北京时间文本、未保存原始时间戳的待发送样本，时间显示“未提供”，不反推或猜测。已生成的历史通知正文不改写、不自动重发。
- 管理台预览与真实告警使用相同的当前平台时区规则；预览不发送消息。
