# 管理台首页 HTTP 500：运行环境原地替换（2026年11月11日）

## 根因与证据

用户访问 `http://127.0.0.1:8090/` 收到 JSON 错误，而不是 HTML 登录页。实际排查结果：

- `/` 返回 500，`/assets/console.css`、`/assets/app.js` 返回 404；`/health/live` 仍为 200。
- 日志报错 `FileNotFoundError` / `RuntimeError`，缺失的是 `.venv/Lib/site-packages/newapi_watch/web/index.html`。
- 原进程从该安装包目录加载，但磁盘上的 `.venv` 后来变成 editable 安装；`__editable__.newapi_watch-0.4.0.pth` 指向 `src`，原包目录已不存在。
- 新 Python 进程能从 `src/newapi_watch` 找到完整页面，说明源码与发布 wheel 的页面没有丢失；旧进程持有的文件路径失效。

结论：开发与正式进程共用虚拟环境，并在服务运行期间切换安装模式，导致静态文件被移除。不属于 DeepSeek 鉴权、管理账号、数据或前端样式问题。没有证据确定具体由谁执行了环境切换，不作归责。

## 已执行修复

1. 使用 SQLite backup 保存现有控制库与各平台数据库，备份位置只记录在本机 `artifacts/console-env-repair-integrity-before.json`。
2. 新建独立 `.venv-console`，按带 hash 的 `requirements.txt` 安装运行依赖，非 editable 安装已验证的 v0.4.0 wheel；使用 copy 安装模式。
3. 在隔离 DEMO 控制目录先验证首页、12 个页面资源、账号登录、平台列表和总览。
4. 核验 8090 所属进程后，只停止本项目旧 Console，使用 `.venv-console` 启动同一控制目录与端口。未操作 NewAPI 进程。
5. 重新验证 `.env`、master.key 与解密后平台/模型/绑定配置摘要未变。
6. 将 `.venv-console/` 加入 Git 与 Docker 构建上下文忽略项；未修改业务代码、未升级模型或密钥。

## 正式启动方式

在项目目录运行以下命令。**仅在现有服务已经停止、8090 未被占用时启动，避免重复机器人连接。**

```powershell
cd D:\work\newapi-mcpserver
.\.venv-console\Scripts\python.exe -u -m newapi_watch console --control-dir data/console --host 127.0.0.1 --port 8090 --insecure-cookie
```

当前后台服务已经用这个独立环境运行，不需要再执行一次。账号与密码文件保持不变；不要把密码发到群聊。

- `.venv` / `.venv-dev`：开发和测试，允许按项目需要同步依赖。
- `.venv-console`：正式服务专用。不要对正在运行的此环境执行 `uv sync`、editable 安装或原地重装。
- 正式更新：先验证新版本安装包/环境，备份数据，停止确认过的 Console，再切换并重启；不要在运行中替换其安装文件。
- `--insecure-cookie` 仅用于本机 HTTP；本次仍只监听 127.0.0.1，未开放公网。
