# pure-admin 全量迁移与本地开发验收（2026年11月11日）

## 采用的方案与执行裁决

以用户的《前端重构开发文档-pureadmin.md》为前端方案真源，覆盖之前 React/Ant Design 的选型。采用官方 pure-admin-thin 6.2.0 的 Vue 3/TypeScript/Vite/Pinia/Element Plus/PureTable 布局与组件；趋势图使用按需注册的 ECharts。

- M0–M3 已实现；M4 的静态输出/SPA 路由/package-data/CI/多阶段 Dockerfile 配置已准备。用户明确当前只做本地开发，所以**没有执行 wheel/sdist 打包、Docker 构建、容器发布或远程部署**。
- 文档中“后端契约冻结”的含义在本轮落实为原接口兼容保留。用户此前已经要求的错误告警、用户阈值、报告调度，不能只靠前端伪造，所以新增 `console_extensions.py` 路由和 `monitoring/` 服务；未改变原有 Cookie/CSRF 和 API 包络。
- 后端本地以 `.venv-dev` 中源码运行，不再反复安装发行包。真实平台配置保持原样；只迁移了每平台 SQLite 的加法 Schema v3 并补齐查询数据。已做 SQLite 一致性备份。
- 没有 Git 仓库，因此没有伪造 Git 提交；未启用未获授权的子代理。采用作者自审 + 自动化与浏览器验收，而不是宣称存在外部独立审查。

## 数据链路修复与边界

- 去掉固定“前50条”行为：工具提供全渠道汇总、分页、has_more；系统提示要求用户索取全部时继续翻页。
- 渠道只展示白名单运维字段（含模型、分组、权重/优先级、累计 quota 等），不把转发 Key/原始 other/IP 当作“完整数据”返回。
- 统计与错误查询先向当前绑定平台管理接口完整分页读取时间窗口，再聚合；窗口失败不发布完整覆盖，不把上游失败当作零。
- 指定历史窗口补数不会推动定时采集游标，也不会把不连续历史补数伪装成连续采集覆盖。实时窗口以本次完整上游数据替换对应缓存，避免混入已删除/过期的本地旧记录。
- 渠道内存合并缓存15秒、日志窗口查询缓存30秒，以减少群聊/界面重复读取；来源仍明确是绑定平台管理 API。不是承诺每个请求都重新触发一次上游 HTTP。
- 有界分页与45秒日志取数预算。超出上限、授权失败、429、超时均明确失败；不能将上游未记录/已清理/当前令牌无权读取的数据凭空补出。
- HTTP 错误按渠道+HTTP码+错误码+模型聚合；日志去重、冷却到期汇总；需要 @所有人时使用企微 text 的 mentioned_list，而不是只追加“@所有人”文字。
- 模型已调用工具但平台返回429时，返回平台查询失败；不再误诊为模型不支持工具，也不允许模型说成“全部正常/用量为0”。
