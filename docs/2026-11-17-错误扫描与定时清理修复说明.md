# 2026-11-17 错误扫描与定时清理修复说明

## 已完成

### 错误爆发时的扫描可靠性
- 错误扫描采用冻结时间窗口，在首个请求前保存窗口；逐页保存续扫页码、已处理条数和分页边界。
- 每页的错误去重、错误桶累加、通知入队与检查点在同一个 SQLite 事务内提交。
- 40 秒扫描预算耗尽时标记待继续；45 秒外层取消、429、网络错误或服务重启都不会丢弃已提交页。
- 完整窗口游标仅在全部页面校验通过后推进，不能用已读日志的最大时间戳代替完成进度。
- 分页总数、大小、ID 顺序发生可检测变化时，保留已接受事件并重新检查同一窗口；去重避免重复计数。
- 未完成的扫描不报告来源故障恢复。存在未完成扫描时，不自动过期其错误去重记录。
- 通知冷却继续生效；先处理的页面可先提醒，后续新增错误仍计入冷却桶，不能把这类真实新增计数当作重复告警。

### 上游账户界面
- 删除表格中的时区/“零点至查询时”和“缓存已过期，待刷新”辅助文字。
- 保留今日金额、实际统计截止时间，以及真实读取失败提示。

### 请求日志与其他清理任务
- 请求日志页增加“上游实时 / 本地记录”切换，以及“定时清理设置”入口和当前本地保留策略。
- 路径：平台设置 → 数据管理 → 自动清理 / 本地请求日志保留天数。
- 沿用按平台独立设置的 1–365 天保留期，按日志产生时间计算。通常每小时检查；积压批次一分钟后继续。
- 修复操作记录清理满 500 条和辅助表清理满 1000 条后未触发短重试的问题；页面显示各类清理数量和积压状态。
- 验证本地请求日志、历史通知/告警、已结束任务、命令/操作记录、探测记录、传输收据、过期清理预览和错误去重/空桶维护。
- 活动告警、待投递/发送中通知、等待机器人投递的完整任务结果，以及监控游标/检查点保持保护。
- 平台停用时仍可执行本地清理，不启动真实监控；关闭自动清理后仍只维护必要的任务有效期、收据和临时预览。

## 边界
- 自动清理只操作本服务本地 SQLite 数据，不删除上游 NewAPI 日志；上游实时列表中的历史记录不会因为本地清理而消失。
- 监控模式仍不全量复制上游请求日志；本地历史为空不代表上游没有请求。
- 保存保留策略不会立即清空数据，沿用下一小时开始检查的保护行为；首次确认前保留旧版本历史清理范围。
- 旧版本已经跳过的历史窗口不会自动回放，避免未经确认向群聊补发大量旧消息。
- 上游持续改写历史记录或超过分页上限时仍会明确标记未知，不将部分扫描伪装为完整成功。
- 日报/周报待定功能未修改。没有新增真实配置、表结构迁移、生产部署、Git 提交或推送。
