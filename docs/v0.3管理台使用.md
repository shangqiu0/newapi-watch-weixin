# 多平台管理台使用方式（v0.3）

企业微信智能回复的重点、模型配置和真实验收边界，优先阅读《企微智能回答链路.md》。本管理台是配置和查询入口，不是只在网页上接模型。

## 本机初始化管理台

不带注册页面，使用一个部署者预置账号，初始密码随机生成且不在对话中回显。

```powershell
cd D:\work\newapi-mcpserver
# 先停止旧监控终端，再同步安装；不要停止NewAPI。
uv sync --frozen --extra dev
uv run newapi-watch console-init --username admin --control-dir data/console
# 初始账号写入 data/console/initial-account.txt，自己在本机查看，勿发送到群聊。
uv run newapi-watch console --control-dir data/console --host 127.0.0.1 --port 8090 --insecure-cookie
```

`--insecure-cookie`仅限本机HTTP开发。公网部署必须TLS并移除此标志，Secure/HttpOnly/SameSite会话、CSRF和登录限速由服务端处理。

原有.env可显式导入成**停用**平台，导入不会连接机器人或发通知：

```powershell
uv run newapi-watch console-import-env --control-dir data/console
```

登录后配置平台、绑定bot和群Webhook、配置模型服务，再按需启用。启用原有机器人前先停止旧单站服务中的同一机器人，不能两个进程争抢一个长连接。已有单站历史业务数据不会自动复制进新平台空间。

## 隔离与绑定

- 平台业务库是`data/console/platforms/<UUID>/watch.sqlite3`，相同渠道ID也不混用。
- 平台NewAPI管理凭证、模型Key、bot secret和Webhook加密存储，GET接口仅回has_secret，空值编辑保留已有秘密。
- 每个智能机器人只有一个活跃绑定；多个bot与多个群Webhook可以同属一个平台。模型和聊天工具固定在绑定平台，不能用提示词切换平台。
- 平台配置变更只重建该平台监控实例；停用保留历史；不重启NewAPI。没有注册/机器人用户角色分层。
- 通知回执按平台/通知ID/目标/配置版本区分。部分目标失败时，已成功目标不重复发送同一通知。

## 备份与凭证保护

控制库`control.sqlite3`和`master.key`需要共同安全备份，此外备份每个平台SQLite。丢失主密钥不能恢复已有凭证；控制库已存在却缺密钥时程序拒绝生成替代钥匙。初始账号文件包含真实密码，不要提交版本控制，不要发送到群里。Windows生产部署需自行设置目录ACL；POSIX会以私有文件权限创建。

## 已验证与未验证

- 隔离/加密/会话/CSRF/退出/限流、bot唯一绑定、模型工具越界拒绝、多目标通知回执已用真实SQLite和HTTP边界测试。
- 浏览器在独立离线控制库上完成错误/正确登录、新增平台、绑定、模型配置、问答和桌面/移动截图。浏览器模型是离线协议替身，不能充当用户真实模型的验收证据。
- 当前真实模型Key没有配置，真实企微自然问答要按《企微智能回答链路.md》配置后再测。未自动导入、启用或修改用户真实.env。
- 测试总计Windows/Linux各153项通过，覆盖率87.15%。还有SDK的2条弃用警告。
