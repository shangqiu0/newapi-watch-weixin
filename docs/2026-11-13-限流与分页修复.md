# 2026年11月13日：平台限流、刷新选择和列表分页修复

## 根因与改动

1. **429**：NewAPI管理接口的监控/机器人/页面查询/报告共用同一个平台客户端，但原来没有请求节流；429还会按0.5秒量级立即重试，分页会连续扫描。在每平台客户端新增共享请求启动节流，默认1.2秒。遇429停止本次重试并进入所有来源共享冷却：基础60秒、连续限流默认指数退避至15分钟（用户配置更长基础冷却时不缩短）；Retry-After数字或HTTP日期给出更长等待时尊重更长值。冷却期间不发网络请求，也不把失败当空数据。配置热更新不清除正在生效的冷却。
2. **刷新平台改变**：平台ID仅存Pinia内存。现在用现有VueUse useStorage只保存选中的平台ID，不保存令牌、密码或业务数据。刷新加载授权平台列表后恢复选择；旧ID失效/平台删除时回退；注销仍清空上下文。不同标签页不自动互相切换平台，以免旧视图混入其他平台。
3. **列表不能翻页**：useRemote发起请求时将data置空，列表组件把total传为0，Element Plus分页组件据此把第2页重置为第1页。新增usePagedRemote只保留同一平台最后一次成功的总条数，加载期不归零；切换平台仍立即清空数据和总数，避免串数据。六个列表统一20/50/100条、跳页，修改每页条数/筛选/平台时回第1页。
4. **重复读取**：监控渠道结果写入查询短期内存缓存，页面无需立即重新分页读取；用户分页复用30秒/最多8个关键字的缓存；日志缓存用请求时间范围做稳定key，不再在每分钟边界失效。失败与部分分页不会缓存为成功。不引入业务日志镜像。

## 配置入口

管理台 → 监控策略 → 请求节流：
- min_interval_seconds：默认1.2，可设0.1..60秒。
- rate_limit_cooldown_seconds：默认60，可设5..3600秒；Retry-After可要求更长等待。

监控工作台显示本平台剩余冷却时间。查询返回429及Retry-After响应头，并给出可读的限流提示。不同平台分别控制，不互相阻塞。这里只降低自身造成的429，不绕过上游IP/令牌限额；其他服务共享出口或上游限额过低时，仍可能限流。
