# 2026年11月17日：监控工作台迭代使用与升级说明

## 本次范围

本轮实现上游今日消费、本地数据保留与受控删除、平台设置整合、后台任务/运行记录入口精简，以及基于 Element Plus 和 pure-admin 的控制台布局与交互优化。继续保持单管理员、按平台隔离的独立监控服务，不修改 NewAPI。

实际组件栈仍为 Vue 3、TypeScript、Element Plus、pure-admin、Lucide。参考 Ant Design、TDesign 的配置分区、工具栏与状态反馈思路，不引入 React，也不同时安装多套基础 UI 库。

## 1. 上游账户：今日已用（¥）

入口：监控管理 → 上游账户。

- 可用余额仍读取该上游普通用户的 `/api/user/self`。
- 新增今日消费列，通过该账户的 `/api/log/self/stat` 读取消费 quota，按该账户已确认的人民币参数换算。
- 统计范围为“统计时区今天00:00:00至请求捕获的截止时间”，不是近24小时。支持账户单独设置统计时区，留空继承所属平台时区。
- 原来的 used_quota 明确标为“累计已用”，不能与今日消费混淆。
- 列表刷新不自动并发拉取全部上游。已启用余额监控的账户按原周期检查余额，并读取/复用今日统计；仅按需查询的账户点击“刷新数据”。
- 今日统计缓存300秒，复用现有可选 Redis，Redis不可用时使用本机缓存；没有新增必需基础设施。
- 保留来源、统计截止时间、新鲜度。跨零点不展示昨天用量为今天值。失败时不把缺失数据当零；有当天旧值则保留旧值并标注失败/过期。
- 今日统计失败不覆盖正常余额，不产生零余额误告警。不支持统计接口时不会自动扫描全量日志，也不会使用主平台管理员令牌回退查询。
- 普通用户统计能否使用现有访问令牌由二开平台决定；不兼容时需要对方开放对应接口/认证。统计遵循上游消费日志口径，不是实际充值成本或退款后净支出。
- 支持列显隐、恢复默认，小屏通过横向滚动查看完整列。

## 2. 统一平台设置

入口：配置管理 → 平台设置。

| 分区 | 内容 |
| --- | --- |
| 接入与时间 | 平台名称、用户 ID、访问令牌、时区；平台地址只读 |
| 金额显示 | 主平台 quota 参数、候选参数读取与人民币预览 |
| 模型服务 | 兼容模式、地址、模型、密钥、连接诊断 |
| 数据管理 | 按类别保留天数、自动清理、手动预览和执行 |
| 运行记录 | 管理操作与命令调用记录 |

各分区独立保存，不把其他分区旧值重新提交。服务端串行化同平台配置的读、合并、校验、写入，避免并发更新互相覆盖。密钥留空保留原值，不回显。

切换分区、离开页面、切换平台或关闭标签页时，未保存的编辑有提示。模型连接测试使用已保存配置；有草稿时需要先保存。测试会消耗少量模型 Token，不会发送企微消息。

监控阈值、检查频率、限流仍在“监控策略”；通知目的地仍在“机器人与通知”。Redis地址、数据库路径、服务主密钥不作为可随意在线编辑的业务参数。

## 3. 数据保留与清理边界

**只删除本服务本地数据，不删除 NewAPI 原站日志。请求日志页面默认实时查询上游，所以清理本地日志后，上游旧日志仍然可以被查到。**

默认兼容现有策略：

- 本地日志：30天。
- 历史告警、已结束通知：30天。
- 已结束查询任务：1天，沿用旧策略；可自行延长到7天等值。
- 运行与操作记录：30天。
- 各类别允许1～365天；自动清理可关闭。必要的活动任务7天有效期、传输收据过期维护不受展示数据开关影响。

旧配置未显式保存保留策略时，继续按旧范围自动清理，不自动删除此前长期保留的失败通知/已恢复告警；首次保存该分区会提示并确认完整清理范围。

后台通常按小时检查，短事务分批清理；有积压时更快续跑。首次启用服务、修改保留设置后，首次检查延后一小时，不在保存页面时立即执行清空。缩短保留期或重新启用自动清理有确认提示。

平台停用后仍允许本地维护任务工作，但不会因此启用上游轮询、模型或企微连接。

### 手动清理

1. 选择当前平台、数据类型与截止时间，或在列表选择记录。
2. 点击“预览清理/删除选中”，查看符合条件条数、受保护条数、本批条数。
3. 确认当前平台与范围后执行。

每批最多100条；更多历史可以再次预览清理。预览有效期10分钟，执行时重新检查状态与版本；在预览后被重试、更新或进入执行状态的记录会跳过。重复提交同一已完成预览不会再次删除另一批数据。

| 对象 | 限制 |
| --- | --- |
| 通知 | sent/historical/cancelled/dead 且没有投递租约才可删除；pending 必须先取消；sending 受保护 |
| 查询任务 | 仅已完成/已取消/失败任务；尚待返回机器人原会话的完成结果受保护；运行中先取消 |
| 告警 | 已恢复/历史事件可从历史列表移除并清除展示正文；保留最小ID与代数以维持去重，新一轮事件仍正常出现 |
| 命令记录 | 按截止时间清理，不逐条擦除关键操作记录 |
| 远程渠道/用户/日志 | 不提供远程删除功能 |

通知“取消投递”只表示未再发送，绝不等同“已投递”。已经发送到企业微信的消息无法通过本地删除撤回。

本地日志清理会更新/使本地统计覆盖失效，不能把缺失范围标为完整。监控游标、冷却和活动状态不作为普通列表记录清空。SQLite 文件不一定立即缩小；不会每次删除后执行阻塞式全库压缩。

## 4. 页面迁移

- 查询任务合并到“数据查询 → 按需统计 → 后台查询任务”，后台执行、取消、重试、机器人任务查询能力保留。
- 原操作审计合并到“平台设置 → 运行记录”，区分管理操作与命令调用。
- 原金额显示、模型服务独立页迁入设置分区。
- 已删除4个废弃页面实现，未保留两套平行编辑器。

旧地址兼容跳转：

- `/console/tasks` → `/console/statistics?tab=tasks`
- `/console/currency` → `/console/settings?tab=currency`
- `/console/model` → `/console/settings?tab=model`
- `/console/audit` → `/console/settings?tab=records`

告警、通知、任务支持当前页选中批量删除；删除末页最后一项会返回有效页，切换平台清空选择。常规分页与HTTP错误日志的游标继续读取不混用。

## 5. 升级与回退

- 控制数据库由版本2增量升级到版本3，新增 `operation_records` 表与平台/时间索引，用于最小操作追溯；历史表、配置和密钥不重建。
- 平台数据库结构仍使用现有版本6，本轮保留配置写入既有加密平台JSON，统计样本/清理预览写入现有metadata。
- 实际启动新版本前，先在服务停止时备份控制数据库、各平台数据库和原 `master.key`；若数据库仍在写入，应使用 SQLite 一致性备份，而不是只拷贝主文件忽略WAL。
- 本轮开发验证没有对真实数据库执行该迁移，也没有改动真实 `.env` 或保存参数。
- 回退使用升级前的一致性备份及匹配代码。旧程序会拒绝更高版本控制库，不能仅替换旧代码强行覆盖新库。
- 删除历史数据不可通过回退代码恢复，执行前确认范围并按需备份。
