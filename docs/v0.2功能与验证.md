# v0.2 功能、升级与验证

日期：2026-11-10。版本：0.2.0。沿用所有使用者权限一致、外部独立部署的设计。

## 1. 新增功能

### 多日与多维统计

- `统计 近7天`、`统计 近30天`、`统计 2026-11-01~2026-11-03`。
- `排行 模型 近7天`、`排行 渠道 昨天`、`排行 用户 近7天 按调用`。
- `图表 近7天`：每日趋势；`图表 模型 近7天`：模型排行；同样支持渠道、用户。
- 排序支持`按消耗`、`按调用`、`按错误`、`按Token`。调用排序按type=2消费记录数，不把上游重试记录伪称最终请求数。
- 最多31个自然日、20项排行。日期两端包含自然日，底层时间窗左闭右开。禁止未来日期，DST和非整小时偏移时区使用精确边界。
- quota保持整数原始单位，Token、成功/错误记录和活跃用户/渠道分别统计。原始日志未采集齐、超保留期或当天未结束时标记数据不完整。
- PNG仅使用#名次标签；模型名或用户/渠道ID对应信息在同一回复文本中列出，不要求部署中文字体，也不会把外部任意字符串绘入图片。
- 日报保留原命令，增加模型/渠道消耗前三和“当前未恢复告警数”。当前状态不是当日告警触发次数。
- 单次正文/图表/渠道领榜使用同一事务采集的统计快照。图表有有界容量，取消请求后等待后台绘图线程结束才释放槽位。

### 告警操作闭环

- `告警 列表`展示完整ID、firing/resolved和确认状态。
- `告警 确认 <ID>`只记录人工已知晓，不停采集、不修改NewAPI、不伪造恢复、不撤回既有通知。再次触发的新generation不继承旧确认。
- `告警 静默列表`只显示未过期项。原有设置/取消静默命令仍可用。
- `通知 死信`查看失败通知；`通知 重试 <通知ID>`只允许dead项单条重新入队。
- 重试是“允许通知worker再次投递”，不是操作命令当场再次发群。保留原先限速/退避/顺序，文字会标注历史通知重试。图片重试仍为原历史图片。
- 同一个重试请求跨进程重启仍不会再次重置次数；同键不同通知拒绝；pending/sending/sent不可直接重试。

### 脱敏审计与健康

- 审计记录来源(local/http/wecom)、HMAC身份指纹、命令分类、结果和耗时；不存原始命令、参数、回复、姓名、BotID或密钥。身份指纹不用于权限判断。
- 无效参数、上游错误、操作冲突、异常和取消不会记作成功。审计按时间分页，并按日志保留天数清理。
- `健康`及HTTP接口展示渠道/日志新鲜度、死信和积压、机器人是否配置/是否认证、后台任务故障。DEMO不会连接真实机器人。

## 2. 新增HTTP接口

全部使用相同`X-API-Key`，没有角色分层；旧接口响应保持兼容。

| 方法与路径 | 用途 |
|---|---|
| GET `/api/v1/statistics` | 结构化统计快照 |
| GET `/api/v1/statistics/chart` | PNG图表 |
| GET `/api/v1/silences?page=1&page_size=20` | 有效静默分页 |
| GET `/api/v1/notifications/dead?page=1&page_size=20` | 死信分页 |
| GET `/api/v1/audits?page=1&page_size=20` | 脱敏审计分页 |
| PUT `/api/v1/alerts/{id}/acknowledgement` | 幂等确认当前generation |
| POST `/api/v1/notifications/{id}/retries` | 幂等请求死信重试 |

统计参数：`start`、`end`为必填ISO日期；`dimension=model|channel|user`；`metric=quota|calls|errors|tokens`；`limit`默认10最大20；`channel_id`可选。图表另有`kind=trend|ranking`。非法日期/范围/枚举返回400，未认证401；不存在资源404、状态冲突409、图表繁忙429。列表默认20最大100。

POST重试需要8–128位`Idempotency-Key`，同键同资源返回`duplicate=true`；同键不同资源409。经`POST /commands`触发确认/重试也需幂等键。审计、静默列表等只读命令不需要。

```powershell
$headers = @{ 'X-API-Key' = $env:WATCH_API_KEY }
Invoke-RestMethod 'http://127.0.0.1:8088/api/v1/statistics?start=2026-11-01&end=2026-11-07&dimension=model' -Headers $headers
Invoke-RestMethod 'http://127.0.0.1:8088/api/v1/audits?page_size=20' -Headers $headers
# .env由程序读取，不会自动注入当前PowerShell；示例变量请在本地设置，勿将真实值发到群里。
```

## 3. 升级方式（不重启NewAPI）

**此次开发未替用户停止或重启现有监控服务。** 验证过程中发现原`.venv`入口程序被服务进程占用，使用独立`.venv-dev`完成验证；没有强制终止用户进程。

1. 在原监控终端按Ctrl+C，仅停止本监控服务，不停止NewAPI。
2. 备份`WATCH_DATABASE`指向的SQLite数据库。停服后再复制；保留原数据，不要删除`data/`。如使用在线备份，应使用SQLite backup而非只复制正在写入的主文件。
3. 更新依赖和本地包：

```powershell
cd D:\work\newapi-mcpserver
uv sync --frozen --extra dev
uv run newapi-watch check
uv run newapi-watch serve --host 127.0.0.1 --port 8088
```

无需新增.env字段。首次打开v1库时，自动以事务新增确认、重试请求和审计表，升级到schema2；既有快照、日志、告警、通知队列均保留。测试已覆盖重复启动、迁移失败回滚、未来版本拒绝。

降级时恢复升级前备份后再运行旧版；不能在已有v2数据上直接强改`PRAGMA user_version=1`。迁移本轮只在隔离测试数据库验证，未主动打开/迁移用户生产数据库。

Docker用户可更新为本地镜像`newapi-watch:0.2.0`，或按原Compose重建。NewAPI回环地址若在宿主机，容器中需要可达宿主地址；不要照搬127.0.0.1。

## 4. 独立验证与副作用边界

- 未修改真实.env，未执行真实渠道探测/启停，未连接真实企微机器人、未发真实群消息。
- 群/私聊帧通过真实官方SDK构造回复，仅替换外部传输，覆盖图片回复、去重和审计来源；不冒称本轮已通过用户实际群聊端到端操作。
- 自动化使用隔离SQLite、模拟NewAPI、DEMO和断网Linux容器，不复用生产数据或当前机器人连接。
- 原有0.1真实接口、群Webhook和机器人认证结果保留在`docs/实现说明与验证.md`；新功能真实交互需用户重启后验收。
