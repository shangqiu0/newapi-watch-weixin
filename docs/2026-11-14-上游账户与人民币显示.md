# 上游普通用户账户与人民币金额显示

开发日期：2026年11月14日。适用：多平台 Console 模式。

## 一、本次交付

1. 每个监控平台可以保存最多30个独立上游账户，不替换本平台管理员访问令牌。
2. 每个上游使用自己的平台地址、普通用户访问令牌、New-Api-User，以及独立人民币参数。
3. 普通账户只读 `/api/user/self`，校验返回用户 ID 与配置一致、余额必须是有效整数，不回退管理员接口；不读取其他用户、渠道或全平台日志。
4. 支持接入启停、监控启停、人民币提醒/恢复阈值、检查间隔、冷却、恢复通知、查询机器人与通知目标绑定。
5. 主平台用户额度、日志消费、统计/任务结果和图表、余额策略、聊天工具和回复使用统一的后端金额注解。图表仅在绘图时将后端金额转为绘图库数值，不在前端自行换汇。
6. 单账户慢请求不阻塞其他上游；并发最多3个，来自同主机的账户共享节流。401/403/429、超时、缺失余额或身份不符明确失败，不把未知余额当作零。

所有群成员权限一致，不新增网站注册或多用户角色。Webhook是单向推送目标，不是聊天查询入口。

## 二、金额口径

```text
人民币显示额度 = quota / quota_per_unit * usd_exchange_rate
人民币阈值写入 quota = ceil(人民币阈值 / usd_exchange_rate * quota_per_unit)
```

这是平台额度显示价格，不是充值实付款、渠道进货成本或实时外汇报价。每个来源独立配置，不能从截图的 ¥ 符号推测倍率。

本次对用户提供站点的公开 `/api/status` 做了一次无令牌只读核对，白名单字段声明为CNY、500000 quota/系统单位、显示倍率7.3。没有将该值自动写入任何真实配置；其他平台不得照搬。

- 金额与参数使用 Decimal/十进制字符串，不使用浮点金额保存阈值。
- 未确认参数时保留原始 quota 并明确标注，不伪装成零元或自动猜7.3。
- 小额非零显示 `¥<0.01`；常规金额两位小数、千分位。
- 主平台修改显示参数不重新计算既有整数 quota 阈值；只有明确编辑人民币阈值才换算。仅改名称/路由/启停不会因显示舍入漂移。
- `Channel.balance` 属于供应商原始余额，币种不可靠，未自动套用用户 quota 的人民币公式。其累计消耗 `used_quota` 可以按平台额度规则显示。

## 三、网页使用步骤

### 当前平台的人民币设置

1. 选择监控平台，打开「金额显示」。
2. 点击「读取平台参数」，核对候选值；不支持该状态结构的二开平台可手工填写实际参数。
3. 勾选已确认并保存。读取只是预览，不会自动改变运行配置。
4. 打开「用户额度」「余额监控」核对数值；人民币阈值编辑由服务端转换。

### 新增上游账户

1. 选择所属监控平台，打开「上游账户」→「新增上游账户」。
2. 填上游根地址、该账户在上游的用户ID、普通用户访问令牌。不是用于 `/v1/chat/completions` 的模型 Key，也不是本平台管理员令牌。
3. 首次可保持监控关闭保存，再编辑读取该上游人民币参数。亦可直接手工填写已核对参数。
4. 选择允许查询的本平台机器人；留空表示不向机器人开放，网页管理员仍可按需查询。
5. 设置人民币提醒/恢复线、周期、冷却，选择通知目标，然后启用接入/监控。
6. 页面“查余额”执行一次自身接口查询；列表读取最近样本，不为每次刷新遍历所有远端账户。

编辑访问令牌留空保留原值；更换地址或用户ID需要重新填写令牌。删除只移除本地接入和策略，不删除上游账户。凭证、身份或策略变化后，旧采样上下文不复用，旧待发送上游提醒停止自动投递。

### Webhook 与机器人主动提醒

- 群Webhook：在「机器人与通知」中配置本平台Webhook，订阅“账户余额”，在上游账户里选作通知目标。
- 企业微信机器人：先在需要接收告警的会话中发送 `会话ID`，将返回值填到该机器人绑定的“余额主动提醒接收会话 ID”。随后在上游账户中选作通知目标。
- 只对显式选择的机器人和接收会话主动发送，不能把聊过机器人的所有群或私聊作为广播目标。
- 机器人发送沿用SDK，必须取得成功回执才能记录目标已投递；未连接或发送失败保留失败状态，按既有通知重试机制处理。
- 自动投递是至少一次语义，网络或进程中断后可能重试，不承诺严格恰好一次。
- 某些企业微信版本/会话不支持主动消息时，应使用Webhook；本次未进行真实企微发送验收。

查询命令：

```text
上游余额
上游余额 上游账户名称
上游余额 账户ID
会话ID
```

“上游余额”最多直接查询当前机器人已绑定的5个账户；更多账户时先提示指定名称/ID，防止一条消息大量请求。大模型启用时新增 `get_upstream_accounts`、`get_upstream_balance`，同时支持更自然的提问；仅列出账户元信息不能当作已经读取余额的依据。

## 四、API与兼容

新增端点均位于已登录 Cookie + 写操作CSRF的Console路由下：

| 方法 | 路径（省略 `/console/api/platforms/{platform_id}`） | 作用 |
| --- | --- | --- |
| POST | `/currency-previews` | 读取主平台CNY参数候选，不保存 |
| GET | `/upstream-accounts?page=1&page_size=20` | 当前平台账户分页及最近样本 |
| POST | `/upstream-accounts` | 添加上游账户 |
| PATCH | `/upstream-accounts/{id}` | 编辑，空令牌保留原值 |
| DELETE | `/upstream-accounts/{id}` | 移除接入 |
| POST | `/upstream-accounts/{id}/balance-queries` | 按需查询自身余额 |
| POST | `/upstream-accounts/{id}/currency-previews` | 读取该上游CNY参数候选 |

主平台金额参数通过既有平台PATCH的 `currency` 保存。余额策略写接口仍接受旧整数quota字段；网页明确编辑金额时，额外发送 `balance_amounts`，按用户ID标明要转换的字段，例如：

```json
{
  "balance_amounts": {
    "7": {"threshold_cny": "100.01", "recovery_threshold_cny": "120"}
  }
}
```

它与完整监控策略一起提交；GET返回的 `_display`、`_cny` 为显示注解，不作为默认重新计算旧阈值的指令。

账户配置保存在原控制库的加密平台JSON中，公有DTO不返回令牌。最近采样、失败原因、冷却和通知继续使用各平台独立SQLite。没有新数据库表或生产库迁移，不保存上游原始完整业务日志。沿用现有 `master.key`，不要删除或重新生成。

## 金额表单与精度

- 参照 [New API 官方计费与支付配置](https://docs.newapi.ai/zh/docs/guide/feature-guide/system-settings/settings-billing)：默认 500000 内部 quota 对应 1 USD；站点使用「元」显示时，按该站点的人民币兑美元汇率换算。默认值不是所有站点的实际配置。
- 「平台设置 → 金额显示」或上游账户表单里的「读取平台参数」只更新草稿。站点未明确声明 CNY、字段缺失或手工修改参数后，需要在该站点核对并确认；不会把未知 quota 标成元。
- 阈值表单展示两位小数，支持粘贴 `¥10,000.00`。本平台用户监控未编辑的阈值保持原整数 quota；只保存实际编辑的金额字段。上游账户则保留原人民币阈值，换算参数变化时，以该人民币阈值重新计算比较用 quota。
