# 1.1 查询引擎说明

## 目标

大范围统计不再让企业微信请求一直等待完整日志扫描：

1. **汇总优先**：模型/用户/渠道排行优先读取 NewAPI 已落盘的聚合接口。
2. **精确任务异步化**：汇总接口不支持、数据结构不兼容或用户明确选择“精确统计”时，创建可续跑查询任务。
3. **监控优先**：监控检查优先于人工查询，人工查询优先于历史重查询；所有请求仍共用平台限流和429冷却。
4. **最小持久化**：SQLite只保存任务状态、分页进度、去重ID和已脱敏的聚合结果，不保存完整原始日志正文。
5. **可选Redis**：Redis只缓存短时聚合结果，不是任务进度真源；Redis不可用会自动回退到内存缓存和SQLite任务。

## Redis配置

Redis支持是可选依赖：

```powershell
uv sync --extra redis
```

`.env`中可以配置：

```dotenv
WATCH_QUERY_REDIS_URL=redis://:密码@127.0.0.1:6379/0
WATCH_QUERY_CACHE_TTL_SECONDS=30
WATCH_QUERY_TASK_REQUEST_BUDGET=5
WATCH_QUERY_TASK_SECONDS_BUDGET=20
WATCH_QUERY_TASK_MAX_REQUESTS=10000
```

不配置 `WATCH_QUERY_REDIS_URL` 不影响监控和后台任务。缓存只保存脱敏的聚合JSON，键使用平台、管理令牌、用户范围的哈希命名空间，不保存令牌本身。Redis连接失败会熔断约30秒并回退内存缓存，不把Redis密码写进错误提示。

## 统计数据口径

- `/api/data/`：模型和时间维度的上游小时聚合。
- `/api/data/users`：用户和时间维度的上游小时聚合。
- `/api/data/flow`：渠道/用户/分组/模型的聚合；当前不带可靠的时间轴，因此渠道趋势不能伪造。
- 聚合接口没有返回错误数、活跃用户/渠道等指标时，页面和机器人显示“未提供”，不能显示为0。
- 上游聚合是已落盘数据，不是实时完整日志；未保存或已清理的历史无法补齐。

## 精确任务

网页：平台 → **按需统计** → 勾选“精确统计任务”，或打开 **查询任务** 页面。

机器人：

- `查询今天模型消耗排行`：优先使用上游汇总。
- `精确统计今天的用量`：创建后台任务，立即返回任务ID。
- `任务 q_<任务ID>`：查询当前机器人绑定会话创建的任务。
- 任务完成后，服务会尝试回到原来的企微群/私聊发送摘要；机器人未连接或投递失败不会标记为已投递，最多退避重试3次。

任务状态：等待执行、正在读取、限流等待、已暂停、已完成、已取消。暂停时已完成页的进度会保留；分页总数变化只拆分当前未确认的时间区间，已确认的其他区间不会重复合并。

任务限制：

- 单任务默认累计最多10000次上游请求；达到上限暂停，不发送部分统计。
- 单批默认最多5页，并在页边界检查20秒预算；单页HTTP另外受30秒超时限制。每个成功页立即保存进度。
- 单平台同时保留的活动任务最多50个；超过返回429，避免查询洪泛影响监控。
- 活动任务最多保留7天，超过后取消；完成/取消/失败结果自最后更新起保留24小时，由每小时清理任务回收。
- 日报/周报路线不使用本功能，本版本继续按原已知BUG延期，不在本次改动中恢复大日志扫描。

## 错误状态码查询

网页日志页输入HTTP 400–599后，不再宣称完整总数，而是扫描错误日志页并返回本批匹配记录；“继续查找”使用10分钟游标继续。机器人精确统计工具支持 `status_codes`，错误明细工具支持 `http_status` 和游标。

如果上游错误记录没有可识别HTTP状态码，返回未知数量并标记 `filter_complete=false`，不能把没有匹配的结果解释为没有错误。

## 数据库与运行边界

- 平台业务SQLite由schema v4增量升级至v6，仅新增query_jobs，不修改既有监控规则、通知回执或原始额度。
- 部署新版本前应先备份平台数据库；回滚旧程序需恢复升级前的备份，旧程序会拒绝高版本schema。
- 任务调度当前仅支持一个Console服务进程。Redis用于缓存，不提供多实例任务租约或全局分布式限流；不能据此同时启动多个服务进程连接同一平台机器人。
- 已发出的HTTP不会被优先级强行撤销；排队时监控优先，429冷却对所有优先级共同生效。
- 日志接口不是事务快照；已冻结时间窗、总数变化和重复页有校验，但上游同时清理/修改数据仍可能导致暂停。不会保证任意平台、任意大数据量都能秒级精确完成。
- 已确认进度逐页提交；用户取消或平台凭证变更后不继续发布旧结果。网页单管理员可看本平台任务；机器人任务只允许原绑定/会话/发起人查询。
- 主动通知只有收到成功回执才记投递成功；网络中断或进程崩溃可能造成至少一次重试，消息带任务ID帮助去重，不宣称跨网络严格一次投递。
- 新Redis环境配置需重启监控服务本身生效，不需要重启NewAPI。没有自动修改用户现有.env，也没有启动常驻本地服务。

## API行为

- `GET /console/api/platforms/{id}/statistics` 只做快速只读查询或返回 `requires_task=true` 的计划，不创建后台任务。
- `POST /console/api/platforms/{id}/statistics-queries` 发起交互统计，支持汇总优先与精确任务；沿用Cookie/CSRF。
- `POST /console/api/platforms/{id}/query-tasks` 显式创建精确任务，重复提交同一上下文条件会复用活动任务。
- `GET /console/api/platforms/{id}/query-tasks` 分页列表、`GET .../{task_id}` 详情、`DELETE .../{task_id}` 取消、`POST .../{task_id}/retries` 手工继续。
- `GET /console/api/platforms/{id}/query-status` 返回脱敏缓存状态及批次预算，不返回Redis地址/密码。
- 统计网页已通过POST提交，GET历史访问不会因为浏览器预取而启动重查询。
