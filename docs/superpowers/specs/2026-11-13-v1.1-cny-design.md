# 1.1：人民币额度与企业微信机器人能力核查

日期：2026年11月13日。状态：**设计待确认，尚未实现**。

本次依据用户的 1.1 需求、当前本地代码和 NewAPI 官方源码进行核查。没有访问线上控制台、读取真实业务数据、运行机器人、变更阈值、发布或提交代码。不能把本地代码核查视为线上验收。

## 一、用户需求与本次范围

1. 系统设置中的额度使用人民币数值输入、显示，内部自动换算。
2. 核查配置 NewAPI 管理员访问令牌后，现有企微对话机器人能查询并返回哪些真实数据。
3. 沿用多平台、平台与机器人绑定隔离、所有机器人使用者权限一致的现有要求。
4. 不改变“外部监控策略服务”的定位，不增加原始业务日志长期镜像。
5. 日报/周报的大日志量 BUG 仍按既有决定延期处理。

## 二、人民币额度设计（待确认）

### 2.1 推荐的人民币含义

人民币表示“平台额度的人民币显示值”，不是用户充值的实际支付金额，不是渠道供应商的余额，也不是实时外汇报价。每个平台使用自己的换算参数。

公式：

```text
显示人民币 = 原始 quota / quota_per_unit × usd_exchange_rate
内部 quota 阈值 = ceil(人民币阈值 / usd_exchange_rate × quota_per_unit)
```

阈值向上取整有明确的比较依据：整数 q 满足 `q < ceil(T / rate)` 与按精确额度判断 `q * rate < T` 一致。余额恢复使用同一转换边界。金额显示四舍五入，不用显示的两位小数反算旧阈值。

例子仅用于说明：quota_per_unit=500000、usd_exchange_rate=7.3 时，500000 quota 显示 ¥7.30；这不是对任何实际平台配置的确认。

### 2.2 每平台配置，而非全局硬编码

拟新增独立的 CurrencyConfig：

- 是否已确认：旧平台缺少配置时为未确认。
- quota_per_unit：每 1 系统美元额度对应的 quota，正数 Decimal。
- usd_exchange_rate：每 1 系统美元额度对应的人民币，正数 Decimal。
- 参数来源：手工设置或平台状态接口；记录确认时间。
- 人民币为固定的目标显示币种；不能将 CUSTOM 的任意符号/倍率自动认定为人民币。

优先提供“读取平台参数”操作，由服务端读取绑定平台的 `/api/status`，只提取白名单字段并给出候选值，经管理员确认保存；支持手工填写。此读取沿用平台共享节流、超时与 429 冷却，不引入第二套请求链路。旧版本缺失字段、返回无效值时提示手工配置，不偷偷采用 7.3。

读取参数只给预览，不自动重写正在运行的监控规则；不每轮监控都重新请求汇率。不调用 `/api/option` 批量读取管理员设置。

### 2.3 页面和通知

- 平台编辑：增加“人民币换算”设置、参数来源、换算示例。
- 余额监控：告警阈值、恢复阈值用人民币输入；当前余额和阈值显示 `¥`，保留原始 quota 供详情核对。
- 用户页面：余额和累计消耗采用同一平台换算参数。
- 额度型日志/统计：累计消耗、排行、图表提示及企微数据回答采用相同口径，原始字段不删除。
- 企业微信余额告警：显示用户、人民币余额、人民币阈值、时间；保留结构化 quota 与换算参数证据。
- LLM 工具收到后端计算的人民币字符串与单位信息，模型不能自己猜汇率。
- 未确认换算参数：明确提示“请配置人民币换算”，保留 quota，不显示成零元、不伪装为人民币。允许既有 quota 策略继续工作。
- 小额非零余额避免显示成绝对零；列表以两位小数为主，详情可显示六位小数。

**不能直接转换 `Channel.balance`。** 这个字段是渠道供应商返回的独立余额，当前 DTO 没有可信币种声明。只有明确是 quota 的字段使用额度公式。渠道余额暂保留原值并注明单位未确认，不与用户额度混用。

### 2.4 1.0 兼容与精度

- 继续保存、比较整数 quota；不将数据库金额字段整体迁为浮点人民币。
- 老平台没有 currency 字段也必须能读取、启动，旧阈值及启用状态保持不变。
- 保留原有 quota 请求字段语义；人民币写入使用新增且明确标注币种的 DTO，服务端负责 Decimal 校验、换算和范围检查，不只靠前端计算。
- 同时提交人民币与 quota 且不一致时拒绝，不能猜用户意图。
- 未编辑金额仅修改名称/启用/路由时，原 quota 阈值必须逐位保留，避免显示舍入造成阈值漂移。
- 参数变更需要预览已有规则的显示差异；不静默重算旧 quota 阈值。管理员明确修改人民币阈值时才重新换算。
- 金额对外使用十进制字符串；拒绝 NaN、Infinity、负阈值、零/负换算率、超长小数和超出范围的额度。支持余额为负数的显示，但不允许设置负监控阈值。
- 保持每平台隔离，历史告警正文/回执不回写，不按当前汇率伪造历史人民币数值。

## 三、当前企微机器人真实能力

### 3.1 调用路径与令牌含义

`BotGateway → Assistant → Tools → DataQueries → NewAPIClient → 机器人绑定平台`。

管理访问令牌用于 `Authorization: Bearer ...`，并附带 `New-Api-User`。它与“模型调用 Key”是两种凭证。仅有管理员令牌不等于启用大模型，需要另外启用并配置兼容服务地址、模型 ID 和模型 Key。

当前工具清单由 `src/newapi_watch/llm_tools.py` 的 SCHEMAS 决定，一共 7 项；不是将管理员可访问的全部接口交给大模型。

### 3.2 已接入大模型的工具

| 工具 | 可查数据 | 示例 | 边界 |
| --- | --- | --- | --- |
| get_channels | 渠道总数、启用/手动禁用/自动禁用/未知数量；渠道分页明细 | 现在有多少渠道？哪些自动禁用了？ | 汇总覆盖完整读取的列表；明细每页最多100，不能将第一页称为全部 |
| get_channel | 指定渠道 ID 的名称、状态、类型、模型、分组、优先级、权重、响应时间、余额和用量等白名单字段 | 看一下渠道93的详情和支持的模型 | 不进行可用性探测；手动禁用不等于故障；供应商余额单位未知 |
| search_users | 关键字搜索用户，返回 ID、用户名、显示名、quota、used_quota、请求次数、状态、分组 | 查一下用户张三的余额和累计用量 | 搜索语义取决于上游；并非专门的按ID精确查询工具；不返回密码/密钥 |
| get_statistics | 成功消费记录、错误记录、quota、Token、活跃用户/渠道、模型/渠道/用户排行、趋势 | 今天消耗多少？近7天哪些模型用量最高？ | 最多31个自然日；LLM工具排行固定前10；指标是消耗/调用/错误/Token |
| get_statistics(chart=true) | 同上并生成图表，在企微回复中附图 | 画近7天的消耗趋势；画用户用量排行 | 与上一项是同一个工具，不额外计入7项；需要查询完整并成功绘图 |
| get_errors | 指定日期范围错误日志，按渠道过滤，返回时间、模型、渠道/用户、状态码、错误码与脱敏错误信息等 | 看看今天渠道93报了什么错误 | 当前只读type=5错误记录；不提供任意原始正文/提示词导出 |
| get_alerts | 本监控服务当前平台的告警状态、确认信息等 | 最近有哪些告警？哪些还没确认？ | 来源是本地告警状态，不是上游NewAPI业务日志；工具支持分页 |
| get_capabilities | 说明本机器人能力及限制 | 你能查哪些内容？ | 不查询业务数据 |

### 3.3 来源、完整性与限制

- 渠道：`/api/channel/` 完整分页读取；约15秒短缓存，监控与查询复用。
- 用户搜索：`/api/user/search`；关键字约30秒缓存，不按企微发言人绑定NewAPI用户。
- 错误与统计：按窗口请求 `/api/log/`，完整读取后在内存中聚合；窗口缓存约30秒，不是依靠后台长期存满日志才可查询。
- 告警：当前平台本地监控状态，不能误说来自上游管理接口。
- 所谓“完整”，只覆盖管理令牌可见、仍由平台保留、已成功全部分页获取的数据；不包含上游未记录/已删除日志。
- 统计用 type=2 计算消费记录与消耗，用 type=5 计算错误记录；重试可能多记，不能直接宣传为最终请求成功率。
- 现有窗口日志读取预算45秒，问答总预算50秒，模型工具循环最多10轮；单次回复不是无限量数据库导出。
- 默认上游分页每页100、最多1000页；限流、窗口过大、总数变化或分页不完整会失败/提示未知，不应伪造零用量。
- 渠道/用户有分页工具，但模型实际选择哪些字段、是否继续翻页受问答预算和模型工具能力限制，不能保证一条消息列出任意数量全部明细。
- 大模型失效时可能降级到最近渠道快照或明确说明查询失败；不能承诺每次降级回答都是新发起的实时查询。

### 3.4 命令层存在，不等于自然语言全部可用

以下明确写操作会绕过模型调用确定性命令：

- `告警 确认 <32位告警ID>`：只确认知晓，不等于故障恢复。
- `告警 静默 渠道12 1h` / `告警 取消静默 渠道12`：改变本服务通知静默，不改上游渠道。
- `通知 重试 <通知ID>`：将原通知重新入队，不是直接生成新内容。
- `渠道 12 测试`：虽有命令解析，但 Console/Fleet 当前统一设置 probe_enabled=False，**实际不可用**，不能仅靠管理员令牌开启。

`健康`、`通知 死信`、`审计 列表`、`告警 静默列表` 等存在确定性命令实现，未接入对应 LLM 查询工具。关闭LLM时部分明确命令可经fallback到达；开启LLM后不保证这些只读命令会被正确路由。应标为待完善，而不是直接对外宣称全部可用。

日报可通过统计工具整理文字摘要，但没有独立的日报/周报查询工具。定时日报/周报的大日志量 BUG 仍未彻底解决，不列为已成熟能力，详见 `docs/2026-11-13-日报周报已知问题.md`。

### 3.5 没有开放的功能

- 新增/编辑/删除/启停上游渠道。
- 用户充值、扣款、改额度、封禁用户。
- 创建/泄露令牌或渠道密钥，查看密码。
- 任意SQL、脚本、文件、外部URL调用。
- 在一个机器人里跨绑定平台查询或汇总全部平台。
- 管理员后台所有页面、充值订单/退款/真实利润等未接入数据的任意查询。
- 可靠的超大窗口全量报表/原始日志导出。

### 3.6 上线权限提醒

继续遵守用户既有要求：机器人使用者权限一致，不增加网站多角色。

因此当前不是“每个群成员只能查自己”。能接触到该机器人并发起查询的成员，共享其绑定平台工具的数据可见范围，也可能执行上列本服务告警运维命令。请将机器人放入允许查看此类渠道/用户额度数据的群。管理员令牌存于服务端，不直接发送给用户，也不直接交给模型。

## 四、建议的 1.1 验收

- 老平台旧配置启动、原阈值不变化。
- 两个平台不同汇率，页面、写入、机器人、告警互不串值。
- 人民币正常/零/极小/负余额/超大值及非法参数测试。
- 阈值边界、恢复阈值、未编辑金额不漂移、重复保存幂等。
- 读取参数失败/429/旧版本缺字段时不覆盖已确认参数。
- 上游不可用不显示零余额，渠道供应商余额不误标人民币。
- 金额写入端点未登录/CSRF/平台不存在和删除平台测试。
- 运行完整pytest、Vitest、mypy、Vue/TS类型检查与相关lint；不发布、不打包、不向真实群发送合成测试消息。
- 浏览器验收须遵循本环境浏览器访问限制；被拒绝时不得换工具绕过，应如实报告。
