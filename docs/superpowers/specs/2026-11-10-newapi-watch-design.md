# NewAPI Watch 单权限实施规格

日期：2026-11-10。用户已批准总体方案并授权自主开发、验证、测试。

## 目标
外部独立部署，不修改、不重启 NewAPI；渠道/日志采集、持久化告警和重试、企微群通知、群聊与私聊同一套查询命令、图表日报及扩展接口。

## 已确认变更
不建设多用户平台，不做登录/注册、RBAC、企微身份绑定、用户级数据隔离。所有机器人参与者权限一致；userid 仅用于消息处理与审计。HTTP API 使用统一服务密钥，事件使用 HMAC，这不是角色权限。

## 实施决定
- Python >=3.12，FastAPI、httpx、aiosqlite、Pydantic Settings、matplotlib、官方企微 SDK。
- 已审阅 newapi-monitor 单体实现（当前约2500行，含多用户后台和不需要的功能）；本次采用模块化独立实现，不复制其源码，不引入其后台。保留参考和决策记录。
- 单实例单进程；SQLite WAL、参数化 SQL；监控服务单独升级即可，不实现动态代码热加载。
- 轮询为基线，Webhook 触发核查；不盲信通知文本，不因过期事件回滚渠道状态。
- 命令默认只读；主动渠道测试作为显式受控操作，可统一开关。不上线自动禁用/启用渠道。
- 不依赖 LLM；规则命令能独立运行。MCP 与通用聊天框架后置。
- 无凭证时提供显式 DEMO 模式；生产模式缺失配置拒绝启动。不声称已完成真实企微/NewAPI联调。

## 可靠性与安全
完整分页失败不覆盖快照、不推进日志游标；日志用固定结束窗口及重叠拉取、主键去重。告警和通知入队同事务；通知至少一次投递（不声称恰好一次），指数退避、死信、每目标限速；所有网络有超时，禁止跟随重定向携带凭证。
Webhook 原始报文验签、时间窗、防重放、大小限制；新旧大小写字段兼容。企微消息去重，错误不暴露 URL、key、上游原始错误。统一权限不等于暴露密钥。

## 验收
模拟完整故障/恢复/重试闭环；群私聊同权；分页、网络异常、重启恢复、重复事件、无日志、时区/DST、PNG 生成均有测试。全量 pytest、ruff、mypy、依赖审计及进程级HTTP冒烟。真实平台需用户凭证后联调。
