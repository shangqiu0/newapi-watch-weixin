# 错误监控断点与请求日志清理修复计划

> 执行方式：当前会话内联执行，使用 systematic-debugging、TDD 与 verification-before-completion；不委派、不自动提交。

**目标：** 修复错误爆发时游标卡死/跳过日志；精简上游账户今日消费文案；明确并验证本地请求日志及其他数据的自动保留策略。

**需求依据：** 用户 2026-11-17 的三项明确要求，以及前一轮已复现的 2998 条、3 秒节流、45 秒预算场景。

**架构：** 延用 Python/FastAPI/SQLite 和 Vue/Element Plus。错误扫描采用冻结窗口、逐页持久化状态，事件去重/通知队列/检查点在同一事务提交。预算暂停只表示未完成，完整游标仅在全窗口完成后推进。请求日志继续默认读取上游，不建设全量镜像；本地历史提供明确入口与保留策略，绝不删除上游日志。

## 范围和约束
- 保留平台隔离、共享节流、429 冷却、通知去重，不增加真实平台配置、不调用真实平台、不发消息。
- 不修改日报/周报待定逻辑、不部署、不打生产包、不 Git 提交或推送。
- SQLite 使用现有 metadata 保存有界断点；无新数据库 schema 迁移。
- 去掉表格中的时区/零点范围/缓存过期等冗余文案；保留金额、更新时间及错误状态，不把旧值冒充新值。
- 定时清理只清理本服务已保存的数据，保护活动告警、发送中通知和待投递的完整查询结果。

## 验收重点
1. 完成页不可在暂停、异常或重启后丢失；未完成页不能提前推进完整游标。
2. 上游默认倒序分页、同一秒超过一页记录，不使用最大时间戳冒充完整处理位置。
3. 分页总数、顺序或边界变化时不静默宣告成功；去重防重放。
4. 保留策略配置生效与真正定时执行均验证，不只直接测试 prune 方法。
5. 本地清理不修改上游实时日志，页面清晰表达数据来源。
