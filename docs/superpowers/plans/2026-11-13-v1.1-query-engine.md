# 1.1 交互查询引擎实施计划

状态：用户已批准“汇总优先、重查询可续跑、监控优先”，并允许可选Redis。当前分支feat/v1.1-query-engine，保留此前未提交修复与用户依赖改动。主代理原生执行，不派发子代理、不自动commit/push。

## 架构与边界

- 新建query_engine包：汇总适配、可选缓存、持久化任务、按状态码分页续查。
- Console交互查询走新引擎；保留旧统计方法供旧CLI和日报/周报，不修改报告文件或采集路线。
- 汇总API仅支持其已有指标。未提供错误数/活跃对象数显示“未提供”，不得补零；小时数据覆盖标为上游已落盘，不能声称实时完整。
- 不兼容/缺失汇总接口才创建有界后台精确任务；权限/429明确拒绝或暂停，不通过另接口绕过。
- SQLite迁移至v6仅新增query_jobs；存进度、汇总和去重ID，非业务日志仓库。冻结时间、逐页事务提交、总数变化拆时间窗口，单秒仍无法稳定则暂停，不假成功。
- 每平台任务去重含上下文哈希，任务详情校验机器人/会话；网页管理员可以查看该平台任务。任务取消、失败、暂停、重启恢复。
- Redis仅缓存脱敏聚合JSON，默认不配置；内存LRU兜底。键含平台/令牌/用户scope指纹，TTL有界，Redis故障熔断回退，不存密钥或原始业务正文。SQLite是任务唯一持久化真源。非多实例scheduler方案。
- 请求优先级monitor > interactive > background；不取消已经发出的HTTP，低优先级不能提前占满等待配额；429所有优先级共用冷却。
- 前端复用Vue/Element Plus现有结构，增加查询任务页、状态/取消/重试/结果；统计页展示上游汇总和异步任务提示。
- 没有自动部署/构建；不启动真实机器人，不保存用户新模型Key，有限模型探测使用glm-5.3。

## 任务与验收

1. 缓存/优先级：先写内存TTL/LRU、Redis故障回退/隔离和低优先级让位测试；实现cache.py与RequestThrottle上下文优先级。Redis Python客户端optional extra锁定8.1.0，记录.env.example，验证现有限流测试。
2. 汇总：先写模型/用户/渠道聚合映射、必填缺失拒绝、无数据未知、权限拒绝、不扫日志测试；实现aggregates.py及上游request分类，不复用业务日志存储。
3. 任务：先写重启续跑、分页变化拆窗、取消不覆盖、重复提交/上下文隔离、429/预算暂停测试；迁移005.sql，jobs.py驱动增量聚合，精确成功结果用既有Snapshot格式及明确coverage。
4. 交互：先写API登录/CSRF/平台隔离、LLM创建任务/查任务/状态码续查测试；集成runtime/fleet/console/llm tools；可用时向原绑定会话发通知，否则支持查任务，不能转发其他群。
5. 网页与验证：任务页和统计页、真实Vue组件测试；全量pytest、Vitest、Ruff、mypy、Vue/TS、相关lint。模型Key受限测试与脱敏证据、说明实际限制。
