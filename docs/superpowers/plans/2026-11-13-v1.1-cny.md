# 1.1 人民币额度实现计划

> **面向 AI 代理的工作者：** 使用 executing-plans 原生逐任务执行；未经用户明确授权不派发子代理。步骤使用复选框跟踪。当前为待确认计划，不是已实现功能。

**目标：** 设置页面以人民币输入/显示额度，服务端精确换算并保持1.0已上线quota策略兼容；交付真实企微能力说明。

**架构：** 每个平台保存独立、经确认的CurrencyConfig；统一后端Decimal转换。原有quota字段和策略比较保留，新增明确人民币DTO，不把供应商渠道balance当作quota。

**技术栈：** 现有Python/FastAPI/Pydantic、SQLite加密配置、Vue3/TypeScript/Element Plus、pytest/Vitest；不新增外汇服务或金额计算依赖。

**规格：** `docs/superpowers/specs/2026-11-13-v1.1-cny-design.md`。此方案待用户确认后实现。

## 全局约束

- 金额语义是平台额度显示值；不硬编码所有平台共用7.3。
- 后端Decimal，内部整数quota，人民币外部字符串。
- 阈值从人民币转换使用向上取整，以保持小于/恢复边界语义。
- 未配置/读取失败不默认为零；不重写旧阈值、历史消息和通知回执。
- 不扩大机器人权限，不修复延期的日报周报大日志量问题。
- 不改.env/真实数据库/用户现有依赖改动；不启动机器人，不向真实群发测试，不提交推送、不构建发布产物。

## 审查重点

1. 不同平台的额度倍率/显示汇率不同，禁止全局缓存或平台串值。
2. 1.0阈值换为两位小数显示后，仅改名称也不能改变quota。
3. 修改换算参数不能静默改变旧告警策略，必须展示影响。
4. 缺失状态字段、429和非法汇率不能使余额变成零元或覆盖原配置。
5. 渠道balance单位未知，禁止按用户quota公式转换。
