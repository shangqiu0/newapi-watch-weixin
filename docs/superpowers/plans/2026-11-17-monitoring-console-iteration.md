## 一、目标与范围

本轮针对六项需求：上游账户今日已用金额、日志定期清理、查询任务和操作审计的必要性评估、必要列表删除、配置入口整合、专业控制台体验优化。

### 全局约束

- 继续作为外部监控服务，不修改或重启 NewAPI，不建设全量业务日志仓库。
- 一个网站管理员；不增加注册、多租户或群成员 RBAC。
- 平台、上游账户、机器人、通知目标、缓存和清理范围保持隔离。
- 保留普通用户令牌与主平台管理员令牌的边界，不回退使用管理员令牌查询上游普通账户数据。
- 金额计算沿用 Decimal 和既有人民币换算，不使用大模型或前端浮点计算金额。
- 日报、周报业务及已知大日志量问题继续待定，本轮不修订其调度行为。
- 不改动真实密钥，不重建 master.key；不自行缩短已有保留期或立即删除历史数据。
- 本文中的默认值和界面决策是建议，不代表已经获得用户授权或已写入真实配置。

## 三、方案决策

### 3.1 上游账户新增“今日已用（¥）”

**展示：** 账户、可用余额、今日已用、接入/监控状态、数据更新时间、操作。累计已用仍可查看，明确标注“累计”，可放入详情或可选列。

**统计口径：** 从该上游账户所配置统计时区的今天00:00:00，至本次请求捕获的截止时间；不是最近24小时，也不是主平台全部用户的消费。

1. 首选 `GET /api/log/self/stat`，附带 `start_timestamp`、`end_timestamp`，不加模型/密钥/分组过滤，查询整个自身账户。
2. 使用该账户已有普通用户访问令牌和 New-Api-User；逐站验证二开平台是否支持此接口及该令牌认证方式。
3. 官方当前实现按消费日志汇总 quota，页面说明“上游消费统计口径”；不要声称这是扣除退款后的净支出或充值实付。二开平台若采用不同统计口径，需标注差异。
4. 金额使用该上游账户自己的换算参数。未确认换算时显示原始 quota 与配置引导，不冒充人民币。
5. 上游账户可设置统计时区；默认继承所属监控平台的时区，并在界面显示实际采用值。需要与上游页面一致时允许单独覆盖。
6. 不使用“零点余额减当前余额”，充值、调整额度会使该算法失真；不把累计 used_quota 直接当作今日用量。
7. 上游未提供接口、403、超时、字段缺失时显示“未提供/读取失败/旧数据”，不能显示为 ¥0.00。成功返回真实0才显示零。
8. 上游若关闭消费日志记录，统计覆盖可能不完整；不能仅凭接口成功承诺对方全部计费数据完整。

**负载控制：**

聚合接口减少本服务的分页拉取与传输，不代表上游数据库统计一定快速；仍需请求超时、预算、缓存和退避，不承诺完全消除所有超时或429。

- 复用已配置的余额监控周期；建议统计缓存有效期300秒，不新增高频全量日志采集。
- 页面 GET 列表只读取现有快照，不在每次刷新时同时请求所有上游。
- 单账户“刷新数据”按需读取；批量刷新如实现，必须进入有界队列，遵循同域名限流和429冷却。
- 余额读取与今日统计结果独立：统计失败不能把余额查询判为零余额或触发低余额误告警。
- 复用现有 Redis/内存缓存能力，不新增必需基础设施。缓存作用域包括平台、账户、凭证指纹、统计日期与时区，不在键中写入令牌明文。
- 返回统计窗口、更新时间、来源和新鲜度；跨零点不能把昨天缓存展示成今天值。
- 默认不在接口不兼容时偷偷降级为大范围日志扫描。

### 3.2 请求日志与历史数据清理

**默认边界：仅清理本监控服务的数据，不调用上游删除接口。**

平台实时日志继续由对方平台管理；本服务仅维护必要的监控数据、快照、任务结果与运行记录。请求日志页明确标注数据来源，清理入口放入“平台设置 → 数据管理”。

建议支持的参数：自动清理开关、按类型保留天数、最近执行时间/结果、下次执行时间、手动预览及执行。

| 数据类型 | 建议初始策略 | 保护规则 |
| --- | --- | --- |
| 本地请求日志/监控明细 | 默认沿用30天，可设置1～365天 | 清理后更新本地覆盖范围；不得把残缺范围标为完整统计 |
| 已结束告警/已结束通知 | 建议30天，可设置1～365天 | 活动告警、待投递和重试中记录不可直接物理删除 |
| 已结束查询任务/结果 | 建议7天，可设置1～365天 | 与活动任务超时分开；运行任务必须先取消，不能删库中记录后让 worker 继续执行 |
| 命令调用/必要操作记录 | 默认30天，可设置1～365天 | 不记录密钥、完整问题或模型请求原文；清理操作本身保留一条最小记录 |
| 查询缓存 | 按原有 TTL 淘汰 | 不与持久监控状态共用清空逻辑 |
| 游标、去重键、告警冷却、策略状态 | 不作为普通列表数据删除 | 按监控状态自己的生命周期处理，不能因清空列表而重发历史告警 |

- 旧平台迁移保持原有实际保留策略；建议值不得悄悄缩短存量保留期。任务结果当前1天与建议7天的差异需要显式迁移说明。
- 每小时检查到期记录，使用有界批次和短事务；不在请求线程执行大批量长事务。
- 即使平台监控停用，本地到期清理也应能运行，但不得因此启用上游轮询或通知。
- 缩短保留期、手动按条件清理：先预览当前平台、截止时间和预计条数，确认后执行。预览后新插入或状态变化的记录仍须在执行时重新校验。
- 删除本地快照不保证 SQLite 文件立刻变小；不在每次清理后执行阻塞式全库压缩。空间回收如有必要，作为独立维护动作说明。
- 不增加上游日志删除权限。若用户实际希望删除 NewAPI 原站日志，需要另外确认范围和备份策略，不混入本轮默认任务。

### 3.3 查询任务和操作审计：保留能力、精简入口

**查询任务：** 后台保留；从独立一级入口合并到“按需统计 → 后台任务”标签页。保留进度、结果、重试、取消；新增终态任务删除。机器人原会话任务查询与完成通知不能受影响。这里的任务是本服务的统计任务，不是 NewAPI 的绘图/视频任务。

**操作审计：** 不建设大型审计平台；将现有独立入口整合到“平台设置 → 运行记录”。区分：

- 命令调用记录：来源、操作类别、结果、耗时、脱敏错误标识。
- 必要操作记录：接入/阈值/通知目标/模型配置变更、删除与清理、通知重试等关键操作；只记录对象标识、变更字段名和结果，不记录秘密值。

普通列表浏览不新增海量审计。关键操作不能因没有独立菜单而失去追溯。平台删除后的必要记录仍需可追溯，控制层操作记录可写入控制数据库并带 platform_id，不依赖被停用的轮询进程。

迁移后移除重复页面组件和菜单，旧URL保留兼容跳转；不能只是隐藏菜单却保留两套页面实现。

### 3.4 列表删除范围

| 列表 | 计划处理 |
| --- | --- |
| 平台/上游账户/机器人绑定/余额监控规则 | 保留已有删除，统一确认与依赖提示；删除的是本地接入或规则，不删除远程账户 |
| 已结束查询任务 | 增加单条、批量、按完成时间清理；运行中先取消 |
| 已发送/历史停发/人工取消后的通知 | 增加受控删除；待投递必须先显式取消，不能假标“已投递” |
| 已恢复/普通历史事件告警 | 增加单条、批量清理；活动告警与关联的有效监控状态受保护 |
| 本地请求日志 | 在数据管理中按时间或选定ID受控清理；不向上游发送删除请求 |
| 操作记录 | 优先按保留期清理，不提供随意逐条擦除关键操作痕迹的按钮 |
| 远程渠道/远程用户/平台实时日志 | 不新增远程删除按钮 |

批量操作限定当前平台和明确选中ID，单批最多100条，不将“选择当前页”解释为“选中所有平台/所有筛选结果”。遇到运行状态变化返回冲突与未删除原因。删除最后一页最后一项后正确退回有效页；页码、总数、筛选条件及时更新。

### 3.5 配置页面整合

新增统一“平台设置”页面，采用分区标签页，而不是一个无限长表单：

1. **接入与时间**：平台地址、访问用户、令牌状态、平台时区；保留平台管理中的创建/停用/删除入口。
2. **金额显示**：所属平台的 quota 参数与人民币显示预览。上游账户的独立换算仍在账户编辑器配置。
3. **模型服务**：开关、兼容模式、地址、模型、Key状态、保存和连接诊断；保持每平台独立配置。
4. **数据管理**：保留策略、清理预览/执行、运行结果、必要存储信息。
5. **运行记录**：合并后的命令诊断与必要操作记录，低频使用，不占用一级菜单。

监控策略仍负责阈值、频率、429退避；机器人与通知仍负责绑定和投递目标，避免一项参数在多个地方重复编辑。基础设施配置如端口、数据库路径、Redis连接、主密钥不直接开放随意在线修改；如展示，只做脱敏只读说明。

各分区独立校验、独立保存；切换平台或标签页时提示未保存变更，晚到请求不能覆盖另一平台编辑内容。密钥留空保留，清除必须显式操作，测试连接以已保存配置还是未保存草稿为准必须明示。

### 3.6 前端方案

**推荐：保留 Vue 3 + pure-admin + Element Plus + @pureadmin/table，统一为专业运维控制台。** 现有项目已采用该体系，不默认再次迁移全部组件。

腾讯 TDesign Vue Next 是可选的大厂 Vue 3 桌面组件体系；若“必须整体换用大厂组件库”是硬性要求，应另行批准整套迁移。不要同时堆叠 Element Plus、TDesign、Arco、Ant Design 多套基础组件。

本轮主要优化：

- 统一页面标题、平台上下文、筛选区、工具栏、主操作与表格内容密度。
- 平台切换器始终明显；刷新保留平台选择，空状态明确引导配置。
- 统一表格分页、行选择、列显隐、固定操作列与批量操作反馈；大量数据使用服务端分页，不一次拉取全量。
- 有真实 total 的列表使用页码分页；HTTP错误日志等游标查询保留“继续读取”，不伪造总数和随机跳页。
- 金额右对齐、千分位、统一¥与小额提示；时间按配置时区显示中文格式，保留来源日志时间/请求ID追踪能力。
- 编辑优先使用统一抽屉或标准弹窗，分组明确；避免各页表单宽度和按钮排列不同。
- 复用既有主题 Token，减少大面积装饰卡片、渐变和无意义动画；统一图标与状态颜色。
- 覆盖空、加载、成功、失败、禁用、过期数据状态；补充键盘操作、焦点与必要的无障碍标签。
- 先制作上游账户和平台设置两个代表页供确认，再将设计规则推广至其他页面。

建议导航：工作台；监控管理（策略/用户余额/上游账户）；数据查询（渠道/用户/日志/按需统计含任务/问答）；告警中心（告警/投递）；配置管理（平台管理/平台设置/机器人与通知）。报告调度保持现有功能，本轮不改变启停与任务语义。

## 五、顺序与验收门槛

建议顺序：T01～T03确定数据能力与安全边界 → T04～T07完成可用流程 → T08代表页确认 → T09统一推广 → T10完整回归。

前端设计基线可以在接口确定后提前进行，但不以大量页面重写替代数据正确性验证。

### 审查重点

1. 今日用量错误地按浏览器/服务器时区切日，或跨零点展示昨天缓存；对应T01/T04。
2. 统计失败造成余额被覆盖为0或误触发告警；对应T01。
3. 清理了去重游标/冷却状态导致旧告警重发，或监控停用后历史永不清理；对应T02。
4. 删除与任务执行/通知领取并发，引起已删记录仍执行或被伪标已投递；对应T03/T07。
5. 合并页面保存了另一个平台的配置，或破坏机器人任务所有权；对应T05/T06。

### 本轮不包含

- 删除上游站点原始日志、渠道、用户或账户。
- 全量请求日志镜像/永久日志仓库。
- 日报周报问题修复、额外模型协议开发或全量官方API能力扩展。
- 注册、群成员RBAC、多用户运营平台。
- 未确认的大规模UI组件库替换、依赖升级、生产构建与服务器部署。
